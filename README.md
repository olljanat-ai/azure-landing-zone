# azure-landing-zone

The Azure landing zone of [OneK8s](https://onek8s.github.io/) - one Kubernetes platform for every cloud, which runs
in any public cloud without changes to the applications or to how they are deployed. Azure is the first cloud
implemented; this repository is its landing zone, built with the
[Azure Landing Zones IaC Accelerator](https://azure.github.io/Azure-Landing-Zones/accelerator/) (Terraform, Azure
Verified Modules). The clusters and the container registry are
[aks-terraform](https://github.com/onek8s/aks-terraform)'s; what runs in them is
[aks-fluxcd-platform](https://github.com/onek8s/aks-fluxcd-platform)'s. Portability:
[design section 21](https://github.com/onek8s/onek8s.github.io/blob/main/docs/21-open-standards-and-portability.md).

It implements **phase 1 (Foundation)** of the
[implementation project](https://github.com/onek8s/onek8s.github.io/blob/main/docs/17-implementation-project-and-acceptance-testing.md):
a separate build tenant with management, hub and `sub-aks-dev`, pipelines with OIDC, all Azure Policy assignments in
audit mode and a client VNet that simulates the corporate network. The dev environment's clusters - the two
stateless cells `aks-dev-stateless-az1` and `aks-dev-stateless-az2`, their networks, Key Vaults and Traffic Manager
- are [aks-terraform](https://github.com/onek8s/aks-terraform)'s, created and deleted by its pipeline in
`sub-aks-dev` with this repository's dev apply identity.

**Start here: [docs/deployment.md](docs/deployment.md)** · Lab without Azure Firewall: `scripts/set-network-mode.sh sandbox` · Lab SKUs: [docs/deployment.md](docs/deployment.md#lab-skus) · Requirements → code: [docs/design-mapping.md](docs/design-mapping.md)

```text
Build tenant (not connected to the corporate network)
├── Tenant Root Group
│   └── alz ─┬─ platform ─┬─ management   sub-mgmt   state storage · deployment identities (no monitoring yet)
│            │            │                          management VNet: GitHub runner (ACI), optional jump host,
│            │            │                          private endpoints to every API server
│            │            └─ connectivity sub-hub    hub: Firewall (firewall mode) · private DNS zones
│            │                                       client VNet (simulated corporate network)
│            └─ landingzones ── corp      sub-aks-dev  AKS policy assignments (stacks/aks-policy)
│                                                      onek8s/aks-terraform: vnet-dev-stateless-az1/-az2 +
│                                                      aks-dev-stateless-az1/-az2 (AZ 1, 2), platform and zone
│                                                      Key Vaults, Traffic Manager, container registry
```

| Folder | Content | Deployed by |
|---|---|---|
| [`accelerator/config`](accelerator/config) | Accelerator inputs: `inputs.yaml` (bootstrap `alz_local`, OIDC to this repository), `platform-landing-zone.tfvars` (build tenant platform), `lib/` (ALZ library overrides) | `Deploy-Accelerator` once |
| [`platform`](platform) | Platform landing zone generated by the accelerator (starter module `platform_landing_zone`) – do not edit, run `scripts/sync-platform.sh` | Platform workflow |
| [`stacks/platform-extensions`](stacks/platform-extensions) | Build tenant additions: management VNet, self-hosted runners, optional jump host and test client, client VNet, Firewall rules per zone, AKS deployment identities | Platform workflow |
| [`stacks/aks-policy`](stacks/aks-policy) | Azure Policy of the AKS platform (section 14) on the environment subscription: built-ins and the platform's own `Microsoft.Kubernetes.Data` definitions and mutations (`kubernetes/`, tested with gator) | AKS policy workflow |
| [`network-mode.tfvars`](network-mode.tfvars) | `firewall` (design) or `sandbox` (lab without Azure Firewall: direct peerings, NSGs, NAT gateways) – switch with `scripts/set-network-mode.sh` | all workflows |
| [`environments/dev`](environments/dev) | Parameters of dev: `policy.tfvars` | – |
| [`modules`](modules) | `address-plan` (section 8, with tests), `platform-lookup` | – |
| [`scripts`](scripts) | `sync-platform.sh` (accelerator output), `set-network-mode.sh` (firewall / sandbox), `update-policy-enforcement.sh` (audit switch for every ALZ assignment) | – |

Country codes `fi` / `se`, the test domain and all IP ranges are the examples of the design; replace them with the
prefixes reserved from the corporate IPAM before deploying.
